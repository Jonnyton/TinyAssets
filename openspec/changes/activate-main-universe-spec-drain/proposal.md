## Why

Jonathan's local tray drain can make bounded OpenSpec progress, but it stops
when his computer is off and cannot be owned, repaired, or evolved through the
same phone-chatbot path ordinary TinyAssets users receive. The first
user-owned cloud loop should therefore be the drain itself: a concrete proof
that the complete platform can run and remain user-governed with zero hosts
online.

## What Changes

- Add an activation contract for one private, user-authored, versioned Branch
  loop in Jonathan's main universe that continuously drains the highest-impact
  admissible OpenSpec work in bounded sequential slices.
- Make activation fail closed until the loop has Jonathan-owned provider
  authority, current user/Branch execution authority, a persisted continuation
  trigger with declared catch-up behavior, and a repository-scoped GitHub
  effect grant. Maintainer quota and market compute are not substitutes.
- Require the live connector's existing canonical handles to provide the
  complete owner lifecycle: inspect health and authority, pause/resume/stop,
  edit and inspect an exact diff, dry-test, publish an immutable version,
  activate/rebind, and roll back.
- Preserve the existing drain's fresh-current-main admission, single claim,
  bounded slice, independent review, normal PR/CI policy, and sync/archive
  foldback rather than inventing a privileged cloud patch service.
- Enforce a single-active cutover. The local tray remains the bridge until
  cloud readiness, is stopped before cloud activation, and never drains
  concurrently with the cloud loop.
- Gate acceptance on a computer-off 24-hour run, cloud-worker restart
  recovery, rendered phone-chatbot management and evolution, useful-progress
  receipts, and proof of no duplicate claims or authority fallback.
- Add no top-level MCP handle, raw-secret chat path, market-compute dependency,
  or desktop/operator requirement.

## Capabilities

### New Capabilities

- `user-owned-cloud-loop-activation`: Readiness, activation lease, cutover,
  phone-only ownership, authority provenance, continuity, rollback, and live
  acceptance for an ordinary user-authored cloud Branch loop.

### Modified Capabilities

- `development-coordination-runtime`: Preserve the governed OpenSpec drain's
  fresh admission and bounded delivery semantics when its controller is an
  ordinary cloud Branch rather than the Windows tray supervisor.

## Impact

This change owns the drain instance, its activation/cutover contract, and its
end-to-end proof. It composes rather than redefines the active owners for
browser-only versioned authoring (`complete-independent-full-platform-targets`),
background target authority (`harden-background-branch-execution-authority`),
background provider authority
(`harden-background-provider-execution-authority`), provider custody
(`retire-mcp-provider-secret-deposit` and its requester-authority successor),
persisted continuation (`demand-side-signals`), and scoped/replay-safe GitHub
effects (`outbound-boundary-layer`). Runtime activation is blocked until those
contracts expose a safe Jonathan-owned cloud path; specification and dry
composition can proceed earlier.

Expected implementation affects the main-universe Branch/Goal/Trigger
definition, activation and lease records, canonical-handle routing for
owner lifecycle operations, cloud-worker dispatch, drain receipts/health, and
live connector acceptance artifacts. The local tray code is not promoted into
the cloud runtime and remains enabled only until the single-active cutover.
