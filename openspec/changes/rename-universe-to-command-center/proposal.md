# Rename "universe" to "command center" everywhere a person or an agent reads it

## Why

Founder decision, 2026-10-01: "your harness and ui are all your command center
set up, universe becomes command center, switch ui becomes switch command
center and the opening greating a new user gets becomes welcome commander",
then "universe gone everywhere, it is now command center".

The concept is approved. This change decides how to rename it without breaking
three things that already depend on the old word:

- **Clients holding the old names.** Chatbots cache a conversation's tool list.
  A desktop window can stay open across a deploy. The website ships on its own
  schedule.
- **Code people already built.** Custom UI bundles stored in users' accounts
  read `universe_id` and `universe_name` from the app bridge
  (`tinyassets/onboarding/app_ui.js:346`).
- **Storage.** It has 11 `universe*` tables, `universe_id` in about 80 column
  declarations, `u-<id>` directories, `.universe_id` markers and
  `universe:<id>` actor ids stored in rows. Account deletion finds a user's rows
  by column name, so renaming a column changes what deletion finds.

## What Changes

Five slices land in order. C0 is UI copy, so per AGENTS it does not wait on this
proposal. It is part of this program so the vocabulary is decided once.

- **C0. Copy.** Change every string a person reads in the app, the website and
  the store copy. "Switch UI" becomes **"Switch command center"**. The empty
  thread a new user opens to becomes **"Welcome, commander."** The agent's
  self-reference and served guidance call it **the user's command center**.
  Seed and soul text is included. No key, parameter or route changes.
- **C1. MCP surface (this change's gated part).** The new names become primary
  and the old names are accepted aliases:
  - the `universe_id` parameter becomes `command_center_id`;
  - the targets become `command_center`, `command_center_files` and
    `command_center_file`;
  - the prompt `meet_universe` becomes `meet_command_center`;
  - error codes and response keys are renamed too.

  **The seven handle names do not change**, so the canary's `--assert-handles`
  set does not change.
- **C2. Living docs.** Update PLAN.md, README, `openspec/specs` (including
  renaming the two `universe-*` capability dirs), skills, `docs/reference`, and
  the active changes this program touches. Dated records are not rewritten.
- **C3. Code identifiers.** The founder decided (2026-10-01) to rename them.
  It is a scripted codemod plus review of the non-mechanical sites, run in one
  freeze window that the lead coordinates (design D6).
- **C4. Storage.** The founder decided (2026-10-01) to rename them too. A
  layout guard ships first. Then one locked, idempotent, resumable migration
  runs with a schema-derived inventory, a production-copy dry run, a backup
  and a written rollback, in a measured quiet window (design D7). C4 gets its
  own change directory, because migrations are spec-first.

## Capabilities

### Modified

- `live-mcp-connector-surface`: the prompt catalog renames `meet_universe`, and
  a new requirement covers the command center vocabulary and the alias window.

## Impact

- Public MCP surface: parameter, target, prompt, error-code and response-key
  names. The handles and the canary handle set do not change.
- Resident description budget. The served engine block is 29,839 of its 30,000
  ceiling. A plain swap adds 204 characters (34 occurrences, +6 each) and breaks
  the ratchet, so C0/C1 must trim at least that much. `write_graph` goes from
  11,680 to about 11,722, under its 12,000 limit.
- The first-party clients (app, website, desktop and Android shells, all of
  which wrap the live SPA) move in the same slice. Stored custom UI bundles keep
  the old bridge keys permanently.
- A storage migration (C4), in its own change and after C3.
