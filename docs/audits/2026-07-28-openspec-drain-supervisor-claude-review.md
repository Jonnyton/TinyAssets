# Opposite-provider review: `add-openspec-drain-supervisor`

**Grounding performed (2026-07-28, this worktree):** `openspec_flow.py audit` shows 34 active changes / 842 unchecked tasks / 29 oversized — the drain problem is real and the finish-first pool is workable. `worktree_status.py` exceeded a 150s timeout in this checkout (rc=124), so the 3-minute-hang premise behind the 90s cap is confirmed, not anecdote. `.github/workflows/auto-enroll-merge.yml` exists and auto-enrolls every non-draft PR for squash merge on green required checks, so workers have a real merge path without merge authority. `~/.local/bin/codex.cmd` confirmed to always inject `--dangerously-bypass-approvals-and-sandbox`.

## Findings

**F1 — HIGH: an abandoned same-identity claim wedges the rest of the day into idle.** (design.md §5; delta spec "Drain Workers Preserve Delivery Governance"; `openspec_flow.py:309-318`; AGENTS.md stale-claim policy.) A worker killed at the 90-minute timeout mid-slice leaves a `claimed:<drain-identity>` STATUS row with a same-day heartbeat. Stale-claim reaping needs 24h of no activity, so no later worker may reap it; `check_admission` blocks the same identity from admitting any *other* change; the spec forbids silent claim theft. Every subsequent worker therefore returns BLOCKED and the controller idles until the deadline — exactly the "all-day drain" failure the change exists to fix. The change never defines worker identity naming or the resume path. **Adaptation:** fix one exact drain identity per run (recorded in `state.json`); add a spec requirement + brief instruction that a claim held by the run's *own* identity MUST be resumed/finished/folded first (`check_admission` already permits this — it excludes the same change from `other_owned`); add a resume-path test.

**F2 — HIGH: MERGED is counted on worker say-so; add one controller-side merge verification.** (design.md §2 and Risks bullet 1; delta spec scenario "A slice merges successfully".) The design rejects "trusting prose" but the `DRAIN_RESULT` marker is still worker-authored text, and project memory documents peer CLIs returning fluent, confident false verdicts and false-completion claims. Before incrementing the slice count, the controller should run one check itself — `gh pr view <PR> --json state,mergedAt` (PR state, not branch reachability: squash merges break `rev-list`-style checks per the recorded lesson). Mismatch → count failure, preserve the artifact. This keeps the smallest-safe-v1 delegation (selection/claim/worktree/PR/archive in the worker is right) while removing the single worst self-report from the trust chain. Add to spec + tests.

**F3 — MEDIUM: "merged but foldback incomplete" is undefined and eats the 2-strike failure budget.** (design.md §2, §4.) If the PR merges but sync/archive or STATUS retirement fails, the worker can't honestly return MERGED, so real forward progress becomes FAILED; with `--max-failures` defaulting to 2, one archive flake plus one transient rate-limit ends the day mid-morning. Finish-first self-heals the unarchived change, but the budget accounting is wrong. **Adaptation:** define a distinct terminal (e.g. `PARTIAL <target> <PR>`) that resets the consecutive-failure counter without counting a completed slice, or define MERGED as "PR merged and verified" with foldback debt left to the next worker's finish-first pass. Relatedly, consider a failure taxonomy: exit 127 (CLI unlaunchable) should stop immediately; a rate-limit/auth-signal failure (the 2026-07-21 fleet-loss shape, `fleet_supervisor.py:140-149`) is better treated as idle-and-retry than as one of two strikes.

**F4 — MEDIUM: the write-worker containment story is not what the design implies on this host.** Verified: `resolve_codex()` resolves through PATH/`~/.local/bin` to the bypass shim, so codex workers' `--full-auto`/`-s read-only` flags are placebo; claude write workers use `--dangerously-skip-permissions`. Also, worker-created sibling worktrees (`../wf-*`, design §6) would be *forbidden* by genuine workspace-write — the design only works because the sandbox is bypassed. Not a blocker (the fleet already operates this way), but the design's Risks section and the runbook must state plainly that v1 safety rests on budgets + governance brief + review gates + auto-merge required checks, not sandboxing. Optionally: have the controller pre-create the worktree and pass `--cwd` (also resolves the launch-time chicken-and-egg where `--cwd` can only be the primary checkout the brief forbids editing) — currently deferred as Open Question 2; acceptable to defer, but document the reality now.

**F5 — LOW/MEDIUM: marker-parse tests must cover the template-echo trap.** A prior gate matched its own contract template echoed back. Spec should pin: marker must be the *final* non-empty line, exactly one literal status, placeholder forms (`<MERGED|BLOCKED...>`) and lines containing `|` rejected; plus a test for the `[peer_agent] ERROR` block case. Tasks 2.1 gestures at this; make it explicit.

**F6 — LOW: idle sleep must be interruptible.** The stop scenario covers between-worker exits, but a stop filed during a 30-minute idle should not wait out the interval; require short-interval stop polling capped by remaining deadline, with a test.

**F7 — LOW: provider/model selection under-specified.** How the run picks codex vs claude per worker (fixed flag? alternation?) is unstated, and the `WORKFLOW_CLAUDE_MODEL` fallback lesson (rate-limited `fable` exits 1 with empty stderr) should be carried into the runbook.
