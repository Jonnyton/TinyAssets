> clause sets `display_name=excluded.display_name,
> metadata_json=excluded.metadata_json`, so registering an already-registered
> universe without passing those values replaced the owner's display name with the
> raw id and the registry metadata with `{}` — while reporting success. Fixed by
> `visibility.register_if_absent()`, one guarded predicate now used by BOTH the
> migration and the boot backfill.

> `ensure_universe_registered` unconditionally for every discovered universe on
> every boot — so a universe its owner had named lost that name at the next
> restart. That is pre-existing and worse than the migration instance (every boot,
> not one run), and it is fixed by the same change.
