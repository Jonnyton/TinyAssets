## Findings

- AGREE, C1/C4: a delegated writer's actual `write_graph` call returns
  `universe_access_denied`, leaves the level private and records no owner choice.
  Zero ACL rows yield `read`, not `admin`. The three predicates are equivalent for
  normal stored identities; the two helper implementations fail closed on storage
  errors, whereas the deposit's inline query can propagate an exception.
  Refusal carries no previous/current level. Omitting graph_id resolves the
  authenticated caller's home: OWNER's call updated its bound `u-owned`;
  STRANGER's fallback target was refused. It can publish one's implicit home, but
  cannot bypass ownership of the resolved target.
- AGREE, original C5 reproduction: an undeclared registered universe flips to
  private; unrelated activity reads change from allowed to refused. Corrupt JSON,
  a missing rules row on a registered universe, and a rules row with no remaining
  directory all repair. Second apply writes none of the repaired rows.
- DISAGREE_EVIDENCE, C5 uncovered case: a bare unregistered directory remains
  readable after migration fails with a foreign-key error. See linked concern.
- AGREE, original C8: owner selects metadata_only through write_graph; unrelated
  principal's memory-status dispatcher refuses. Owner, explicit reader grant,
  public and unlisted content reads succeed. No over-tightening reproduced.
- DISAGREE_EVIDENCE, C8 sibling: the universe get_activity dispatcher returns the
  same secret at metadata_only. See linked concern. Other grep hits include
  read_premise/read_canon/read_source/read_output/query_world and
  runs._run_read_allowed; they should be classified by returned capability, not
  blindly switched to a single metadata/content gate. The independently
  reproduced sibling is get_activity.
- DISAGREE_CONCERN, C7 remains a coverage limitation. Deferring a mass fixture
  conversion is reasonable; broad green tests with the double do not prove
  startup/default behavior. Explicit fixtures or strict startup-to-reader tests
  settle it. This alone does not change the verdict. The narrowed concern
  preserves the stated unresolved C7 issue; no specific lost issue established.

`declared_level_source` / `level_was_chosen_by_owner` are read by migration
classification, not by request authorization. They affect which exposure state
the migration preserves; "bookkeeping" should not imply operational irrelevance.
The changed write_graph default reaches the goal consumer, whose
`(visibility or 'public')` normalization preserves its prior default, and the
request guard accepts empty. No additional default-consumer regression found.

Treating an unreadable legacy bit as a migration candidate is conservative for
privacy; it is not permission to expose content. Owner-chosen exposed rows still
take the kept branch. No storage-fault overwrite reproduction was established.

VERDICT: ADAPT. Most important: enforce the content promise across the remaining
readers, or withhold split levels until it is enforced. The concurrent uncommitted
restriction to private/public is not part of this verdict's pinned head.
