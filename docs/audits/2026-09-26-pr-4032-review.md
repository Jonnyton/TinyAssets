## Findings

1. **P1: rotated authorization is discarded after a failed save.**
   credential_refresh.py:242-255 spends, builds records outside the retry, and
   drops the result on deadline. subscription_refresh.py:639-640 swallows the
   resulting RefreshUnavailable as transient and launches the old document.
   There is no recovery record or pending-persistence state. A probe whose
   writer always raised OSError and whose deadline had elapsed called spend
   twice across two invocations while stored remained old. This means replaying
   the spent token, not that a conforming issuer accepts it twice. Admission is
   exclusion, not a guarantee that the later storage operation succeeds.

2. **P1: endpoint trust permits exfiltration and bypasses hardened egress.**
   subscription_refresh.py:378-440 takes issuer/client from unsigned claims;
   :331 resolves before locking and :352 applies that endpoint to the re-read
   credential. discovery.py:138-160 checks metadata issuer equality and URL
   syntax, not trust in the credential's claimed issuer. transport.py:43-62
   permits private/literal hosts; its actual SSRF controls are in request_json
   at :123-148. The new _spend at subscription_refresh.py:205-215 uses httpx
   directly. A patched discovery response with an attacker issuer and
   token_endpoint https://127.0.0.1/token was accepted. An attacker-controlled
   public issuer can name its own collector without any signature verification.
   Pin issuer/client/endpoint provenance to the accepted connection; resolve
   against the locked re-read; use the hardened transport for the POST too.

3. **P1: interactive converse has no refresh hook.**
   providers/router.py:592-629 routes served conversation through
   provider_assignment.py:1436, which snapshots at :1585 without refreshing.
   Only foreground/background workflow launch sites received hooks. A real
   served-router fixture with a stale inline auth document and a recording
   provider produced refresh_hook_calls=0 and provider_calls=1.

4. **P1: renewal invalidates admitted foreground work and cannot self-repair.**
   The two hook sites do precede their immediate custody resolution. However,
   foreground_run_provider.py:860 renews after its receipt was admitted;
   _validate_receipt_parent at :681-684 and :937 still demands the original
   assignment generation/digest. Real manifest renewal returned serving and
   advanced generation 2 -> 3; validating the pre-renewal receipt then raised
   'foreground run provider authority is stale'. Also, the held return from
   ensure_founder_serving (onboarding/serving.py:405-421) is ignored at
   subscription_refresh.py:642. Once the document is fresh, :329 and :641 skip
   renewal, so a failed/crashed renewal does not retry. Renewal needs an explicit
   recoverable lifecycle before admission, preserving accepted model authority.

5. **P1: a rejected unrelated subscription blocks every workflow source.**
   subscription_refresh.py:604-637 iterates all inline subscription services,
   without a selected source argument. Both workflow hooks call it before
   selecting their source. One rejected subscription therefore prevents even a
   healthy HTTP provider from launching. Foreground additionally wraps this
   pre-carrier ProviderAuthenticationError as ProviderAuthorityHeldError at
   foreground_run_provider.py:976-981. Scope refresh and error attribution to
   the source whose invocation is being authorized.

6. **P1: materialized rotations can remain outside the vault.**
   credential_vault.py:2097 uses default .credentials/codex when no home field
   exists. subscription_refresh.py:541 scans only record string values and
   never checks this default. A real materialization followed by writing a
   newer document yielded discovered=None, adopted=False. Separately,
   _on_disk_document_is_newer at credential_vault.py:2088 keeps a newer disk
   document even with the same refresh token; _strictly_newer at
   subscription_refresh.py:566 rejects it. A probe returned keep_disk=True,
   adopt_disk=False. Record-stamp fallback is also asymmetric. Use one typed
   materialized-document resolver and one freshness/version comparison.
   Static resolved outside paths are rejected. The path check then later read
   is nevertheless not descriptor-anchored; ancestor replacement is a TOCTOU
   concern, not a reproduced escape in this review.

7. **P1: native sign-in failure still does not advance the turn.**
   agent_turn_coordinator.py:147-166 recognizes only capacity when finishing
   a failed native round. Auth becomes indeterminate, hence held_native_unknown
   (storage/agent_turn_journal.py:298), excluded by _next_after_signin at :482.
   The Codex exception at providers/codex_provider.py:1006 also carries no
   effect telemetry, so router.py:1279 records None, rejected at coordinator:490.
   Real mixed-provider fixtures, with a native auth failure explicitly carrying
   complete/reaped/no-effects evidence, produced auth_invalid,
   held_native_unknown, native_calls=1, fallback_calls=0. The native probe
   completed its assertions but Windows temp cleanup found a cached SQLite
   handle; this was not a provider or assertion failure. Preserve fail-closed
   behavior for unknown effects; add a proved no-effects auth transition.

8. **P1: exceptions retain credential material through __context__.**
   subscription_refresh.py:128 raises inside JSONDecodeError handling using
   'from None', which suppresses display but retains __context__.doc. Probe:
   JSONDecodeError context.doc equaled the entire malformed synthetic auth
   document. At :216-217 the same construct retains HTTPError.request.content;
   a pinned-head synthetic ConnectError probe found the fake refresh token
   there. Raise after exiting handlers or explicitly detach unsafe context.
   The test at tests/test_subscription_credential_refresh.py:695 only renders
   repr(context), which does not inspect its .doc payload.
   A separate synthetic Codex excerpt, 'refresh token FAKE_OPAQUE_REFRESH was
   already used', retained the opaque token after _redacted_stderr_excerpt and
   matched _terminal_auth_failure. The regex at codex_provider.py:131-138 is
   pre-existing; the new error path reuses it. This demonstrates a sanitizer
   limitation, not an observed real-provider token echo.

9. **P2: phrase matching is not sufficient authentication classification.**
   providers/codex_provider.py:197 accepts generic 'already used', including
   non-authentication errors such as custom_agents.py:799's idempotency-key
   conflict. That predicate match is demonstrable; a real CLI emitting that
   specific message as its terminal error was not observed. More concretely,
   tests/test_providers.py:781 documents the actual exit-zero/401 behavior;
   the new :1005 branch requires nonzero exit, and :1073 still raises plain
   ProviderError for it. Codes/stage/effects must determine classification;
   preserve unknown effect fencing.
