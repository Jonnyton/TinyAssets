## Flags: tracked items that look bespoke where a general primitive would cover them

- **F1, item 7 "Reuse UI/harness/setup designs".** This is worded around UI and harness designs (the `composable-ui-experiences` change). The basic capability is general: publish any shape (workflow, agent, UI) and remix another user's shape into your own universe. The concrete blockers are that the served surface excludes `remix_shape` and refuses publish. Re-scope the row to that general primitive; UI designs are then one instance of it.
- **F2, item 11 "narrow LinkedIn reading".** This is a per-platform item. LinkedIn should be a user-built graph on the generic channel (C26); if it fails, the gap is OAuth2 refresh or transport shape in C26, not a LinkedIn fix.
- **F3, item 5 "desktop/phone previews/captures".** Previews are a composition. The primitives are admitted dependencies plus browser execution in the sandbox (already the item's substance) plus produced-file download (C22). Accept on the primitives, so the platform does not grow a preview feature.
- **F4, item 10 "Retire bespoke patch-request machinery".** This is cleanup, not a user capability. It is fine to do, but it should not count toward basic-capability closure.
- **F5, "Bounded Claude peers" slice.** This is dev tooling; the list already says so. It should not appear among capability slices.
- **F6, durable workspace waiting (C23), mild.** PLAN says retry policy is user-editable composition data, so a platform queue deserves a check: it is justified only because fair cross-run queuing on a shared lock cannot be composed safely by a user graph. The founder restored it explicitly, so this is a note rather than a challenge.
